# Deploying MediDesk to Render

MediDesk deploys as three Render resources, all defined in [`render.yaml`](../render.yaml):

| Resource | Type | What it is |
| --- | --- | --- |
| `medidesk-api` | Web Service (Python) | Django + DRF API, served by Gunicorn |
| `medidesk-web` | Static Site | React SPA built by Vite |
| `medidesk-db` | PostgreSQL | Application database |

## 1. Deploy the blueprint

1. Push `main` to GitHub.
2. In Render: **New → Blueprint**, connect `jhraihan/Medi-Desk`, and apply.

Render reads `render.yaml` and creates all three resources. The first build takes
5–10 minutes, mostly compiling `psycopg2-binary` and `pillow`.

`SECRET_KEY` is generated by Render on first deploy and then left alone. Do not
rotate it casually — it signs every JWT and session cookie, so changing it logs
everyone out.

## 2. Fix the cross-origin URLs

Render appends a random suffix when a service name is already taken, so your real
URLs may not be the ones committed in `render.yaml`. Once both services are up,
check their actual URLs in the dashboard and correct these three variables if they
differ:

- On `medidesk-api`: `CORS_ALLOWED_ORIGINS` and `CSRF_TRUSTED_ORIGINS` → the
  static site's full origin, scheme included (`https://…`).
- On `medidesk-web`: `VITE_API_URL` → the API's URL with the path appended:
  `https://<api-host>/api/v1/`

The trailing slash on `VITE_API_URL` is required. `frontend/src/api.js` issues
relative paths such as `login/`, and axios discards the final segment of a
`baseURL` that does not end in `/`. Without it every request 404s.

`VITE_API_URL` is compiled into the JavaScript bundle, so changing it requires a
redeploy of the static site, not just a restart.

## 3. Create a superuser

The build runs `migrate` but cannot create an interactive user. Open
**`medidesk-api` → Shell** and run:

```bash
cd hms && python manage.py createsuperuser
```

The admin is then at `https://<api-host>/admin/`.

### Optional: demo data

```bash
cd hms && python manage.py seed_demo
```

This creates the demo accounts described in the README. Skip it for a real
deployment — it inserts fictional patients and a shared, publicly documented
password.

## What the build does

`build.sh` runs on every deploy:

1. `pip install -r requirements.txt`
2. `collectstatic` — writes `hms/staticfiles/`, which WhiteNoise serves for the
   admin and Swagger UI. There is no separate web server for static files.
3. `migrate`

Gunicorn then starts with 2 workers, bound to Render's `$PORT`.

Render polls `/healthz/` to decide whether the service is live. That view returns
`{"status": "ok"}` without querying the database, so a slow query cannot take the
service down, and it is listed in `SECURE_REDIRECT_EXEMPT` because the internal
probe arrives over plain HTTP and would otherwise receive a 301.

## Free-tier limits worth knowing

**The API sleeps after 15 minutes of inactivity.** The next request takes
~50 seconds while the container cold-starts. The static site is unaffected, so
the UI loads instantly and then appears to hang on its first API call. This is
the single most common "is it broken?" report.

**PostgreSQL expires after 90 days.** Render deletes free databases at that
point. Back up first:

```bash
pg_dump "$DATABASE_URL" > medidesk-backup.sql
```

**Uploaded files do not survive a deploy.** `MEDIA_ROOT` is a local directory on
an ephemeral filesystem, so the patient documents handled by the `Document` model
are lost on every restart and redeploy. Fine for a demo; for real use, move
`STORAGES["default"]` to S3, Cloudflare R2, or another object store. This is a
pre-existing property of the code, not something the Render setup introduced.

## Local development

Unchanged. Copy `hms/.env.example` to `hms/.env`, then:

```bash
cd hms
python manage.py migrate
python manage.py runserver
```

Omitting `DATABASE_URL` falls back to the local SQLite file. `docker-compose.yml`
still runs the full stack with Postgres and Redis.

## Troubleshooting

| Symptom | Cause |
| --- | --- |
| `DisallowedHost` | `RENDER_EXTERNAL_HOSTNAME` is appended to `ALLOWED_HOSTS` automatically; a custom domain must be added explicitly. |
| CORS error in the browser console | `CORS_ALLOWED_ORIGINS` is missing the `https://` scheme or does not match the static site's origin exactly. |
| API calls 404 | `VITE_API_URL` is missing its trailing slash or the `/api/v1/` path. |
| Admin login fails with a CSRF error | The admin's origin is not in `CSRF_TRUSTED_ORIGINS`. |
| Admin renders unstyled | `collectstatic` failed during the build; check the build log. |
| Redirect loop | `SECURE_PROXY_SSL_HEADER` is required so Django sees Render's forwarded HTTPS. It is set in `settings.py`. |
| First request hangs ~50s | Free-tier cold start, as above. |
