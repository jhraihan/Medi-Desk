MediDesk

Deploy to Render

github.com/jhraihan/Medi-Desk · branch main · free tier · ~20 min

1Push the files

git add render.yaml build.sh requirements.txt hms/ README.md docs/
git commit -m "Add Render deployment configuration"
git push origin main

2Create the blueprint

  1. Sign in at render.com with GitHub.
  2. Grant access to the Medi-Desk repository.
  3. New + → Blueprint (not "Web Service").
  4. Select Medi-Desk → Connect.
  5. Confirm it lists medidesk-api, medidesk-web and medidesk-db, then click Apply.

First build takes 5–10 minutes. Wait for both services to show Live.

3Set the three URL variables

Read each service's real URL from the top of its dashboard page, then set these under Environment → Save Changes:

ServiceVariableValue
medidesk-apiCORS_ALLOWED_ORIGINS https://medidesk-web.onrender.com
medidesk-apiCSRF_TRUSTED_ORIGINS same as above
medidesk-webVITE_API_URL https://medidesk-api.onrender.com/api/v1/

VITE_API_URL needs the trailing slash and the /api/v1/ path, or every request 404s. CORS_ALLOWED_ORIGINS needs https:// and no trailing slash. Substitute your own hostnames if Render added a suffix.

After changing VITE_API_URL: medidesk-web → Manual Deploy → Clear build cache & deploy.

4Create the admin user

medidesk-api → Shell:

cd hms
python manage.py createsuperuser

5Load demo data (optional)

cd hms
python manage.py seed_demo

All five accounts use password Demo!2345: hospital_admin, aisha, reception, pharmacy, rafi.

6Verify

OpenExpect
<api>/healthz/{"status": "ok"}
<api>/admin/Django login, styled
<web> → log inDashboard loads

7Known limits

  • API sleeps after 15 min idle — next request takes ~50 s.
  • Free Postgres is deleted after 90 days. Back up with pg_dump "$DATABASE_URL" > backup.sql.
  • Uploaded documents are lost on every redeploy.
